DKIM2 signature options draft-ietf-dkim-dkim2-spec-07

Apply to both cards below. See the DKIM2 specification (-07) for the details.

Flags (f=, §10.10)

exploded must not be set on the first signature (i=1). It is added automatically when a later signature is sent to more than one recipient (§12.5).

The envelope fields below are ignored. A message whose most recent signature carries nd= is not a Validly Signed DKIM2 Message, so verifying it fails and the next signer needs an out-of-band arrangement.

A Signer must not sign a message that already has DKIM2 header fields unless it is a Validly Signed DKIM2 Message. The message is first fully verified against the envelope it was received with, using the DNS source from Settings.

The received message is signed without being verified, as allowed by an out-of-band arrangement (§12.3). Chain of custody, mf=/d= and exploded checks still apply.

Single hop

Signs the message as it is. A new message gets i=1 and a Message-Instance with m=1; its From header field must be Authentic, so the From domain, like the MAIL FROM domain, must be the signing domain or a subdomain of it (§11, §12.2, §12.4). A message that already carries DKIM2 header fields gets the next i=, subject to the option above.
